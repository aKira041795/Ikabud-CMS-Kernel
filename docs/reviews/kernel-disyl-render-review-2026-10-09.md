# Kernel + DiSyL render — review

## Findings (ranked; each: severity, PROVEN/SUSPECTED, evidence with file:line, why it matters)

1. **HIGH — PROVEN — synchronous Tailwind JIT is on both tenant-entry auth and kernel-owned surfaces.**
   - Daily Ledger's login head unconditionally emits the Google font stylesheet, `cdn.tailwindcss.com`, and HTMX; there is no surrounding DiSyL condition (`templates/modules/daily-ledger/pages/login.disyl:7-12`). The handler renders that template (`modules/daily-ledger/handlers.php:7584-7592`).
   - A tenant's `/login` is deliberately rewritten to an auth-owning entry module's exposed login route (`kernel/Http/TenantEntryRouter.php:102-126`, `kernel/Http/TenantEntryRouter.php:186-199`); Daily Ledger declares auth ownership (`modules/daily-ledger/module.json:7-22`) and exposes `/daily-ledger/login` (`modules/daily-ledger/routes.php:6-9`). Thus the Baron Ledger result is module-owned auth, not the common kernel login shell.
   - Every page extending the kernel admin layout gets an unconditional head script from `cdn.tailwindcss.com` plus an inline JIT configuration (`templates/layouts/kernel-admin.disyl:8-25`). The workbench extends that layout (`templates/pages/superadmin-workbench.disyl:1-7`). `/superadmin/perf` independently emits the same synchronous CDN script (`src/http/page-handlers.php:400-404`).
   - The supplied measurement is 407,279 bytes raw / 123,340 gzip (`.ai/kernel-disyl-review-brief.md:36-38`). The CSP explicitly identifies Tailwind JIT as eval-based and allows both `'unsafe-eval'` and the Tailwind origin (`kernel/Http/SecurityHeaders.php:138-143`).
   - **Why it matters:** this is parser-blocking network work followed by runtime class scanning/style generation on the first mobile page and on kernel administration. It is the strongest evidenced mobile main-thread and critical-path cost.

2. **MEDIUM — PROVEN — both login implementations synchronously fetch HTMX although neither login template contains HTMX behavior.**
   - The common kernel login emits HTMX in its head (`templates/pages/login.disyl:8`) but its form uses a native `onsubmit` handler (`templates/pages/login.disyl:102-103`) and a Fetch request (`templates/pages/login.disyl:128-160`); the only `hx-`/`htmx` occurrence in that file is the script URL (`templates/pages/login.disyl:8`).
   - Daily Ledger repeats the synchronous HTMX head script (`templates/modules/daily-ledger/pages/login.disyl:12`) while its form also invokes a native handler (`templates/modules/daily-ledger/pages/login.disyl:106-107`) and contains no HTMX attribute producer in the template (`templates/modules/daily-ledger/pages/login.disyl:12`).
   - **Why it matters:** the browser must resolve and execute a third-party script before parsing can continue, but the reviewed login documents expose no consumer for it.

3. **MEDIUM — PROVEN — blocking third-party fonts remain on the auth critical path.**
   - The kernel default GUI context sets a four-weight Inter Google Fonts URL (`kernel/App.php:579-582`), and the common login emits `gui.font_url` as a normal blocking stylesheet (`templates/pages/login.disyl:9`).
   - Daily Ledger emits preconnects to `fonts.googleapis.com` and `fonts.gstatic.com`, then a normal stylesheet requesting seven Fraunces/Inter weights (`templates/modules/daily-ledger/pages/login.disyl:8-10`).
   - **Why it matters:** auth rendering depends on another origin and CSS/font request chain; Daily Ledger asks for more faces and weights on the first mobile view.

4. **LOW — PROVEN — kernel shells resend substantial inline CSS/JS on every full render; DiSyL preserves rather than deduplicates it.**
   - The common app layout has a large base style, an optional second override style, and a shell script (`templates/layouts/app.disyl:11`, `templates/layouts/app.disyl:298-299`, `templates/layouts/app.disyl:387-429`).
   - The kernel-admin layout has inline Tailwind configuration, its shell stylesheet, and its toast runtime (`templates/layouts/kernel-admin.disyl:12-25`, `templates/layouts/kernel-admin.disyl:27-197`, `templates/layouts/kernel-admin.disyl:335-358`). Child pages add further blocks, e.g. workbench adds one style and two scripts (`templates/pages/superadmin-workbench.disyl:7-23`, `templates/pages/superadmin-workbench.disyl:1336`).
   - DiSyL extracts and restores script/style blocks during interpreted rendering (`kernel/DiSyL/TemplateEngine.php:755-792`, `kernel/DiSyL/TemplateEngine.php:904-913`); these paths contain no asset registry or deduplication step.
   - **Why it matters:** unchanged shell bytes cannot be independently cached and are reparsed each request. This is secondary to the JIT and blocking network dependencies because no CPU/byte measurement for these blocks was supplied.

5. **LOW — SUSPECTED — a head-only compiled/interpreted regression is possible and is not ruled out by production-template coverage.**
   - With `DISYL_EXTENDS_COMPILED` false, an `{extends}` template is forced interpreted; the flag makes it compiled-eligible (`kernel/DiSyL/TemplateEngine.php:4121-4126`, `kernel/DiSyL/TemplateEngine.php:4153-4160`). Compiled execution uses `executeWithInheritance`, while failures fall through to the interpreted implementation (`kernel/DiSyL/TemplateEngine.php:475-496`). These are separate emission paths.
   - The parity suite does compare direct script/style output (`tests/disyl_parity_test.php:725-736`) and synthetic `head` blocks across inheritance (`tests/disyl_parity_test.php:842-865`), with no declared known divergences (`tests/disyl_parity_test.php:30-39`).
   - **Why it matters:** that is useful observability, but the cited cases do not render the actual kernel layouts/assets as a corpus. No current head-output divergence is proven.

## Answers to the seven questions

1. **Who emits auth/login, and when is Tailwind included? — PROVEN.** The ordinary kernel route dispatches `kernelHandlePageLogin` (`src/http/core-routes.php:8-12`), which renders `pages/login.disyl` (`src/http/page-handlers.php:131-140`); that head has HTMX and the configured font but no Tailwind (`templates/pages/login.disyl:3-10`). For an active tenant with an auth-owning entry module, `TenantEntryRouter` resolves `/login` to that module's exposed auth route (`kernel/Http/TenantEntryRouter.php:44-59`, `kernel/Http/TenantEntryRouter.php:102-126`). Baron Ledger's Daily Ledger template emits Tailwind unconditionally whenever rendered (`templates/modules/daily-ledger/pages/login.disyl:7-12`). The routing split is deliberate; the inconsistent asset policy is template-level drift.

2. **Kernel-owned Tailwind presence — PROVEN.** It is absent from common kernel login (`templates/pages/login.disyl:3-10`), but unconditional in the kernel-admin parent (`templates/layouts/kernel-admin.disyl:7-12`), therefore present on its admin/superadmin children such as workbench (`templates/pages/superadmin-workbench.disyl:1-7`). `/superadmin/perf` is a separate hard-coded document with the CDN (`src/http/page-handlers.php:400-404`).

3. **Duplicate/repeated assets — PROVEN for static templates; SUSPECTED for dynamic shell input.** No exact script `src`, stylesheet `href`, or font `href` is statically repeated within the reviewed common login, app layout, kernel-admin-plus-child heads, workbench head, or perf document: their emission sites are `templates/pages/login.disyl:7-10`, `templates/layouts/app.disyl:7-10`, `templates/layouts/kernel-admin.disyl:7-11`, `templates/pages/superadmin-workbench.disyl:3-7`, and `src/http/page-handlers.php:400-404`. The two unpkg HTMX URLs in `app.disyl` are distinct core and head-support resources (`templates/layouts/app.disyl:7-8`). However, `ApplicationShellViewModel` blindly appends extra URLs (`storage/application-profiles/ark-workbench/src/ApplicationShellViewModel.php:183-195`) and the layout emits every array element (`storage/application-profiles/ark-workbench/layouts/app-shell.disyl:21-25`, `storage/application-profiles/ark-workbench/layouts/app-shell.disyl:90-93`), so duplicate caller input would duplicate markup; current PAL callers add each concrete URL once (`modules/project-audit-ledger/helpers.php:886-891`).

4. **External origins and critical-path status — PROVEN unless noted.**
   - `https://cdn.tailwindcss.com`: synchronous head script on Daily Ledger login, kernel-admin, and perf (`templates/modules/daily-ledger/pages/login.disyl:11`, `templates/layouts/kernel-admin.disyl:8`, `src/http/page-handlers.php:403`) — critical path.
   - `https://unpkg.com`: synchronous HTMX on common and Daily Ledger login (`templates/pages/login.disyl:8`, `templates/modules/daily-ledger/pages/login.disyl:12`) and synchronous HTMX/core extension in the app shell (`templates/layouts/app.disyl:7-8`) — critical path there. Kernel-admin's unpkg scripts are deferred (`templates/layouts/kernel-admin.disyl:9-10`) — not parser-blocking.
   - `https://fonts.googleapis.com`: normal stylesheet on common login/admin through `gui.font_url` (`kernel/App.php:581`, `templates/pages/login.disyl:9`, `templates/layouts/kernel-admin.disyl:7`) and directly on Daily Ledger login (`templates/modules/daily-ledger/pages/login.disyl:10`) — render-blocking.
   - `https://fonts.gstatic.com`: Daily Ledger preconnects directly (`templates/modules/daily-ledger/pages/login.disyl:9`), and CSP permits font fetches there (`kernel/Http/SecurityHeaders.php:157-159`). **SUSPECTED:** actual font requests depend on the returned Google CSS, not repository markup.
   - `https://cdn.jsdelivr.net`: injected as a body-end Alpine script by the workbench shell API (`modules/project-audit-ledger/helpers.php:887-890`, `storage/application-profiles/ark-workbench/layouts/app-shell.disyl:90-93`) — synchronous but at document end, not a head render blocker.
   - CSP also permits cdnjs and Google Maps (`kernel/Http/SecurityHeaders.php:143-160`), but no producer for those origins was found in the reviewed kernel/auth/shell emission paths.

5. **Compiled/interpreted head divergence — SUSPECTED possible, not observed.** The environment flag changes inherited-template eligibility (`kernel/DiSyL/TemplateEngine.php:4121-4126`, `kernel/DiSyL/TemplateEngine.php:4153-4160`), and compiled inheritance and interpreted fallback are distinct (`kernel/DiSyL/TemplateEngine.php:475-496`). It is observable through the parity harness, which compares outputs and exercises inherited `head` blocks (`tests/disyl_parity_test.php:725-733`, `tests/disyl_parity_test.php:842-865`). Those fixtures report no declared known divergence (`tests/disyl_parity_test.php:30-39`), but they are synthetic rather than the real kernel head corpus; a current asset/head divergence was not proven.

6. **Per-request inline CSS/JS — PROVEN.** The common login has one base style, an optional override style, and one inline handler (`templates/pages/login.disyl:10-91`, `templates/pages/login.disyl:128-177`); Daily Ledger has one style and its inline login handler (`templates/modules/daily-ledger/pages/login.disyl:13-72`, `templates/modules/daily-ledger/pages/login.disyl:139-162`). The app shell contributes one base style, optional override, and one script before child blocks (`templates/layouts/app.disyl:11`, `templates/layouts/app.disyl:298-299`, `templates/layouts/app.disyl:387`). Kernel-admin contributes one style and two scripts before child additions (`templates/layouts/kernel-admin.disyl:12-27`, `templates/layouts/kernel-admin.disyl:335`); workbench adds one style and two scripts (`templates/pages/superadmin-workbench.disyl:7-23`, `templates/pages/superadmin-workbench.disyl:1336`). Perf contributes no inline CSS/JS; it relies on Tailwind (`src/http/page-handlers.php:400-404`).

7. **Mobile-cost ranking.** **(1) PROVEN:** synchronous Tailwind JIT, because it combines the measured 123,340-gzip transfer (`.ai/kernel-disyl-review-brief.md:36-38`) with parser blocking and runtime JIT emission (`templates/modules/daily-ledger/pages/login.disyl:11`, `templates/layouts/kernel-admin.disyl:8`). **(2) PROVEN:** blocking Google Fonts CSS/seven-weight Daily Ledger request (`templates/modules/daily-ledger/pages/login.disyl:8-10`). **(3) PROVEN:** synchronous, apparently unused login HTMX (`templates/pages/login.disyl:8`, `templates/modules/daily-ledger/pages/login.disyl:12`). **(4) SUSPECTED:** repeated parsing of inline shell CSS/JS (`templates/layouts/kernel-admin.disyl:12-27`, `templates/layouts/kernel-admin.disyl:335`); no 4x-throttle timing was supplied, so its mobile cost is not quantified.

## Not determined

- Whether the Google Fonts responses actually download every declared weight, or their transfer/timing cost; repository code only proves the requested stylesheet URLs (`kernel/App.php:581`, `templates/modules/daily-ledger/pages/login.disyl:10`).
- Whether any runtime caller outside the reviewed PAL shell builders supplies duplicate or arbitrary `extra_scripts`/`extra_styles`; the API accepts unvalidated strings and does not deduplicate (`storage/application-profiles/ark-workbench/src/ApplicationShellViewModel.php:183-195`).
- Whether real production kernel heads differ with `DISYL_EXTENDS_COMPILED=1`; the checked-in parity coverage is synthetic (`tests/disyl_parity_test.php:842-865`).

## The single highest-value fix, and what it would take

**Replace the synchronous Tailwind CDN/JIT with precompiled, same-origin CSS on the three proven surfaces: Daily Ledger login, `kernel-admin.disyl`, and `/superadmin/perf`.** The replacement sites are `templates/modules/daily-ledger/pages/login.disyl:11`, `templates/layouts/kernel-admin.disyl:8-25`, and `src/http/page-handlers.php:400-404`. It requires compiling the utility classes used by those templates into versioned local stylesheet(s), linking those files, removing the inline `tailwind.config` from the kernel-admin layout, and verifying login/admin/workbench/perf visual parity. Then remove the Tailwind origin from CSP; Tailwind ceases to be an `'unsafe-eval'` driver, although the CDN Alpine build remains a separately documented eval user (`kernel/Http/SecurityHeaders.php:138-143`).
