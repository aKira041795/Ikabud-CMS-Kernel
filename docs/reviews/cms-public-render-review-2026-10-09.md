# CMS public render — review

## Findings (ranked; each: severity, PROVEN/SUSPECTED, evidence with file:line, why it matters)

1. **High — SUSPECTED — the global Alpine/lightbox path is the strongest code-level explanation for mobile main-thread cost.** The measured page's largest transfer is third-party Alpine (16,174 bytes gzip) (`.ai/cms-public-review-brief.md:26-33`). The native layout loads Alpine on every render (`storage/cms-themes/native-default/layouts/public.disyl:105-107`) because it embeds a large Alpine `x-data` lightbox controller globally (`storage/cms-themes/native-default/layouts/public.disyl:259-270`), while its navigation/currency setup is already plain JavaScript (`storage/cms-themes/native-default/layouts/public.disyl:235-255`). This is not proof of the 19-point gap—the missing metric breakdown prevents that—but it is the largest avoidable parse/evaluation and third-party-origin candidate in this code.

2. **Medium — PROVEN — `native-default` emits the same theme stylesheet twice.** The active-theme URL is constructed once in public context (`modules/cms/helpers/78-public-context.php:336-343`), then the same `theme_style_url` is linked at both `storage/cms-themes/native-default/layouts/public.disyl:7` and `storage/cms-themes/native-default/layouts/public.disyl:23`; `cms-public.css` follows at line 24. This is one layout owning the head twice, not layout-versus-page composition. It adds a duplicate render-blocking declaration and unnecessary head work even if the browser coalesces the identical fetch.

3. **Medium — PROVEN — inline CSS is fragmented and some producers accumulate per builder component.** The native shell always contributes its large base block and noscript block (`storage/cms-themes/native-default/layouts/public.disyl:30-105`). Public context then injects independently generated colors and theme fragments (`modules/cms/helpers/78-public-context.php:476-528`); customized header output adds separate mobile and dropdown blocks (`modules/cms/helpers/80-customizer.php:4433-4493`, `modules/cms/helpers/80-customizer.php:4495-4503`); sidebar output adds another (`modules/cms/helpers/80-customizer.php:3674-3692`). Builder documents prepend global and responsive style tags (`modules/cms/helpers/50-builder.php:1688-1704`), while every rendered tabs or flip-box instance prepends non-instance-specific CSS and logo grids may prepend instance CSS (`modules/cms/builder-renderers.php:501-517`, `modules/cms/builder-renderers.php:2087-2107`, `modules/cms/builder-renderers.php:2155-2168`). Necessary dynamic values and responsive rules are mixed with repeatable static widget rules, increasing style parsing and cascade work.

4. **Medium — PROVEN — a module-boundary violation exists in report-approval capability handlers.** `report_approvals` is kernel-migration-owned (`database/migrations/022_report_approvals.sql:1-23`), but CMS capability handlers directly use `app()->db()` without the escalation wrapper (`modules/cms/helpers/55-capabilities.php:1171-1179`, `modules/cms/helpers/55-capabilities.php:1192-1197`, `modules/cms/helpers/55-capabilities.php:1211-1231`). The same module's admin path demonstrates the expected kernel-DB escalation wrapper (`modules/cms/handlers/78-import-export.php:162-177`). This bypasses the documented CMS/helper boundary rather than being a style preference (`.github/instructions/php-module-conventions.instructions.md:49-57`).

5. **Low — PROVEN — the two Google Fonts tags are an intentional JavaScript/no-JavaScript pair, not two head owners, although a second customizer source can independently emit fonts.** One helper returns an async `media="print"` link plus the same URL inside `<noscript>` (`modules/cms/helpers/80-customizer.php:119-142`). The colors renderer calls it and concatenates its style block (`modules/cms/helpers/80-customizer.php:2022-2024`, `modules/cms/helpers/80-customizer.php:2104-2106`); the theme/entity renderer can also call the same helper (`modules/cms/helpers/80-customizer.php:2853-2872`). Thus the observed pair is fully explained by one helper invocation; code has no document-level URL deduplication if both customizer paths select the same family.

6. **Low — PROVEN — canonical public CMS detail rendering bypasses the prescribed entity-view rendering entry point.** The convention requires `{ikb_entity_list}`/`{ikb_entity_detail}` as primary list/detail rendering (`.github/instructions/php-module-conventions.instructions.md:41-47`, `.github/instructions/php-module-conventions.instructions.md:59-60`). CMS does register contracts (`modules/cms/helpers/views/cms_page.disyl:1-28`), but a public page is queried directly and passed to `cmsPublicCanonicalRenderEntityView()` (`modules/cms/handlers/90-public.php:1284-1295`, `modules/cms/handlers/90-public.php:1348-1372`), which resolves and renders `public/entity.view.disyl` itself (`modules/cms/handlers/90-public.php:2643-2644`, `modules/cms/handlers/90-public.php:2776-2812`, `modules/cms/handlers/90-public.php:2833-2834`). This creates a parallel detail pipeline and raises maintenance risk; it is not identified as a PageSpeed cause.

## Answers to the eight questions

### 1. Duplicate emission

**PROVEN.** Composition is handler → canonical renderer → public context → resolved active-theme entity template → active-theme layout: the handler calls the canonical renderer (`modules/cms/handlers/90-public.php:364-384`), that renderer builds `cmsPublicContext` and renders the resolved template (`modules/cms/handlers/90-public.php:2776-2812`, `modules/cms/handlers/90-public.php:2833-2834`), and the native entity template extends the active layout (`storage/cms-themes/native-default/public/entity.view.disyl:1-6`). Public context creates one `theme_style_url` (`modules/cms/helpers/78-public-context.php:336-343`), but that layout emits it before and after its default-variable guards (`storage/cms-themes/native-default/layouts/public.disyl:7-23`).

**PROVEN.** Google Fonts are produced inside customizer fragments inserted at layout lines 25-26 (`storage/cms-themes/native-default/layouts/public.disyl:25-26`). The apparent two-tag pair is emitted in one return value—active stylesheet plus `<noscript>` fallback (`modules/cms/helpers/80-customizer.php:138-142`)—rather than by the child entity page. A possible additional duplicate path exists because both colors and entity-presentation renderers invoke that helper (`modules/cms/helpers/80-customizer.php:2022-2024`, `modules/cms/helpers/80-customizer.php:2858-2872`).

### 2. `builder-public.js` on a public page

**PROVEN.** It is public runtime code, not editor code: it initializes public slideshows, tabs, counters and flip boxes (`public/assets/cms/builder-public.js:1-5`, `public/assets/cms/builder-public.js:8-18`, `public/assets/cms/builder-public.js:119-149`, `public/assets/cms/builder-public.js:184-190`). The native layout gates it on `builder_enabled` and defers it (`storage/cms-themes/native-default/layouts/public.disyl:256-257`). That flag comes from page metadata but is also repaired when rendered HTML contains a builder node (`modules/cms/handlers/90-public.php:2589-2601`). The static-home handler additionally injects the runtime only when builder-node markup exists and the script is absent (`modules/cms/handlers/90-public.php:386-394`).

**SUSPECTED.** The better gate is “rendered document contains a widget needing this runtime,” not merely “page was built with the builder”: the runtime itself no-ops by querying each supported widget type (`public/assets/cms/builder-public.js:8-11`, `public/assets/cms/builder-public.js:119-123`, `public/assets/cms/builder-public.js:148-152`). This would preserve required public behavior while skipping it for builder pages made only of static nodes.

### 3. Eleven inline `<style>` blocks

**PROVEN.** The producers are enumerated in Finding 3: shell base/noscript; colors/theme/custom-code customizer fragments; header/sidebar fragments; builder global/responsive CSS; and per-widget tabs/flip/logo-grid CSS (`storage/cms-themes/native-default/layouts/public.disyl:30-105`, `modules/cms/helpers/80-customizer.php:2104-2106`, `modules/cms/helpers/80-customizer.php:2220-2248`, `modules/cms/helpers/50-builder.php:1688-1704`, `modules/cms/builder-renderers.php:501-517`). Responsive per-node CSS is deliberately collected into one document-level block (`modules/cms/helpers/50-builder.php:1616-1625`, `modules/cms/helpers/50-builder.php:1672-1685`), so it is necessary when responsive overrides exist. Tabs and flip-box static rules are emitted per instance and therefore accumulate (`modules/cms/builder-renderers.php:516-517`, `modules/cms/builder-renderers.php:2100-2107`).

**SUSPECTED.** The measured count of 11 is consistent with these producers, but the exact live-page allocation cannot be reconstructed without its stored builder document and customizer rows; the code makes the count data-dependent (`modules/cms/helpers/80-customizer.php:2219-2248`, `modules/cms/helpers/50-builder.php:1618-1622`).

### 4. Asset versioning

**PROVEN.** Both epoch-looking values are filesystem mtimes. `cmsThemeAssetUrl()` calls `filemtime()` and appends `?v=<mtime>` for active and fallback assets (`modules/cms/helpers/40-theme-settings.php:1262-1279`). They are stable between requests while the deployed file's mtime is unchanged; they do not use request time.

### 5. Is the public CMS page cached?

**PROVEN.** There are two HTML layers. The kernel full-page cache handles eligible anonymous GETs, uses a tenant-scoped instance, and gives CMS pages a 600-second TTL (`src/helpers/page-cache.php:30-36`, `src/helpers/page-cache.php:141-180`, `src/helpers/page-cache.php:231-271`). Module dispatch serves a hit before the handler and stores a successful miss afterward (`src/helpers/module-manager.php:3404-3413`, `src/helpers/module-manager.php:3447-3458`). Static-home CMS HTML also has a tagged CMS cache with ETag handling (`modules/cms/handlers/90-public.php:319-354`, `modules/cms/handlers/90-public.php:405-424`).

**PROVEN.** `/` is not in the skip-prefix list (`config/page-cache-prefixes.php:8-35`), so an anonymous HTML GET for `/` is eligible. Bypasses are `disyl_nocache`/`nocache`, non-GET, authenticated kernel/module cookies, skipped prefixes, and JSON-only requests (`src/helpers/page-cache.php:141-180`); non-200, tiny, and CSRF-bearing responses are not stored (`src/helpers/page-cache.php:244-271`). CMS static-home's inner cache separately bypasses on `disyl_nocache` (`modules/cms/handlers/90-public.php:330-354`). Content/settings/customizer changes invalidate CMS/full-page caches (`modules/cms/helpers/60-cache.php:89-95`, `modules/cms/handlers/50-api-settings.php:85-90`, `modules/cms/handlers/80-customizer.php:358-364`).

**SUSPECTED.** For a tenant whose entry module is CMS, kernel routing rewrites `/` to the module's declared `/cms` landing route: root delegates to `entryLandingPath()` (`kernel/Http/TenantEntryRouter.php:53-86`), which prefers the delegate root route (`kernel/Http/TenantEntryRouter.php:165-205`), and CMS declares `/cms` → `cmsPublicHome` (`modules/cms/routes.php:97-99`). Whether the live domain has that tenant entry configuration, and whether the measured request was a cache hit, is not established by repository code.

### 6. Convention conformance

**PROVEN (conforms).** Routes are declarative and use `cms:functionName` references (`modules/cms/routes.php:5-12`, `modules/cms/routes.php:97-111`); request logic is loaded from handler concerns (`modules/cms/handlers.php:5-32`). Capability declarations exist in the manifest (`modules/cms/module.json:112-140`), while the callable map is in a helper loaded by `helpers.php` (`modules/cms/helpers.php:17-21`, `modules/cms/helpers/55-capabilities.php:5-20`). Root/tenant rewriting remains kernel-owned (`public/index.php:440-445`, `kernel/Http/TenantEntryRouter.php:85-89`).

**PROVEN (violations).** The direct kernel-DB access and parallel canonical detail renderer are Findings 4 and 6 (`modules/cms/helpers/55-capabilities.php:1171-1179`, `modules/cms/handlers/90-public.php:1348-1372`). No stylistic-only issues are reported.

### 7. Most plausible causes of the mobile/desktop gap

1. **SUSPECTED:** global third-party Alpine plus the large global Alpine lightbox controller; this is the largest measured script and is loaded for every native page (`.ai/cms-public-review-brief.md:26-33`, `storage/cms-themes/native-default/layouts/public.disyl:105-107`, `storage/cms-themes/native-default/layouts/public.disyl:259-270`).
2. **SUSPECTED:** render-path CSS work: duplicated theme link, `cms-public.css`, large theme CSS and many dynamic style blocks (`storage/cms-themes/native-default/layouts/public.disyl:7-30`, `.ai/cms-public-review-brief.md:21-36`). Mobile-specific media rules are generated per builder document (`modules/cms/helpers/50-builder.php:1676-1685`).
3. **SUSPECTED:** builder animation/runtime work on mobile: the runtime creates observers and animation callbacks for counters and every `[data-animate]` element (`public/assets/cms/builder-public.js:148-180`, `public/assets/cms/builder-public.js:207-227`), while the layout also eagerly marks all `[data-animate]` nodes at DOM ready (`storage/cms-themes/native-default/layouts/public.disyl:235-241`).
4. **SUSPECTED:** document/DOM and customizer complexity, not transfer size: the measured HTML is 98,706 raw with 11 style blocks (`.ai/cms-public-review-brief.md:35-37`), and header customization injects two additional CSS programs including mobile navigation rules (`modules/cms/helpers/80-customizer.php:4420-4503`).

### 8. Critical-path resources that need not be there

**PROVEN:** the second theme stylesheet link is removable (`storage/cms-themes/native-default/layouts/public.disyl:7-24`). **SUSPECTED:** Alpine can be removed from the global path after replacing/gating the layout lightbox dependency; it is already `defer`, but remains third-party-origin and globally present (`storage/cms-themes/native-default/layouts/public.disyl:105-107`, `storage/cms-themes/native-default/layouts/public.disyl:259-270`). **SUSPECTED:** `builder-public.js` can be omitted on static-only builder documents with a feature-level gate (`public/assets/cms/builder-public.js:8-18`, `public/assets/cms/builder-public.js:119-152`). **PROVEN:** Google Fonts are already made non-render-blocking with `media="print"`; the second source tag is a no-JavaScript fallback, not a second unconditional owner (`modules/cms/helpers/80-customizer.php:138-142`).

## The single highest-value fix, and what it would take

**SUSPECTED — highest value:** remove Alpine from the default public critical path by moving the native layout's global lightbox behavior into the existing native public script (or a small feature-gated local module), then emit/load Alpine only when rendered content actually contains Alpine directives. This targets the largest measured transfer and its third-party connection (`.ai/cms-public-review-brief.md:26-33`) rather than pursuing byte-count bundling, and the layout identifies the global dependency (`storage/cms-themes/native-default/layouts/public.disyl:105-107`, `storage/cms-themes/native-default/layouts/public.disyl:259-270`).

What it would take: inventory the lightbox behaviors represented by the `x-data` controller, preserve keyboard/focus/viewport behavior from that controller (`storage/cms-themes/native-default/layouts/public.disyl:259-270`), implement them in the already-loaded deferred theme runtime (`storage/cms-themes/native-default/layouts/public.disyl:256-257`), add a render-context feature flag for any remaining Alpine-authored regions, and verify public builder widgets because their separate runtime owns slideshows/tabs/counters/animations (`public/assets/cms/builder-public.js:1-5`, `public/assets/cms/builder-public.js:119-180`). The duplicate stylesheet at layout lines 7 and 23 should be removed during the same head-contract verification, but it is not the primary fix (`storage/cms-themes/native-default/layouts/public.disyl:7-24`).
