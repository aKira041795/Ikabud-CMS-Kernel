# Settings Contract Spec — Kernel OS 6.3, Track A (Gate 2 "specify" half)

**Status: DRAFT v0.2 — chair reviewed 2026-10-12 (APPROVE WITH AMENDMENTS; rulings folded below). Awaiting owner approval.**
No enforcement may land from this spec until Gate 2 differential tests prove compatibility on each consuming path.
**Date:** 2026-10-12 (night session) · v0.2 incorporates the chair rulings register (§7).
**Chair's frame:** *"Gate 2 should specify today's behavior, not prematurely declare a cleaner behavior to be today's reality."* A passing schema linter is evidence of declaration quality, not runtime compatibility — keep those gates separate.

**Basis:**
- Chair rulings (settings consult + consolidation consult): characterize → specify → enforce only proven; a central normalizer must never become a second settings authority; per-module `*SettingsDefaults()` helpers are the coverage boundary; `false`/`0`/`""`/`null`/absent must be distinct; rename conflicts stop and report; default changes are compatibility events.
- Gate 0 measurements (2026-10-12/13):
  - **Fields:** 70 modules, 27 with `settings_fields`, **390 fields**. Types: text 168, checkbox 77, select 61, number 55, textarea 16, email 5, password 4, bool 3, time 1.
  - **Invariants:** 0 duplicate keys, 0 missing types, 21 fields without `default`, **14 select fields without `options`**.
  - **Stored (local tenant):** 209 rows, 29 modules. Types: string 155, boolean 50, array 2, integer 2. **51 empty strings**, 8 string-`"1"`, 2 string-`"0"`.
  - **Write coercion** lives in the HTTP handlers only (admin `admin-handlers.php:2810-2845`, superadmin equivalent): checkbox→bool, number→numeric string, select→options-checked string, else `trim(string)`.
  - **Read path:** JSON round-trip preserves `false` / `""` / `0`; absent keys stay absent; the kernel does **not** merge manifest defaults — per-module helpers do.

## 1. Value model (canonical stored form per declared type)

| Declared type | Canonical stored form | Notes |
|---|---|---|
| checkbox | JSON `true` / `false` | preserve `true`/`false` distinctly |
| bool | JSON `true` / `false` — **after characterization** | ⚠ the recorded write coercion names `checkbox`, not `bool`; if `bool` currently falls through to `trim(string)`, making it a JSON boolean **changes write semantics**. Characterize the 3 `bool` fields first; migrate with tests or keep a documented exception. `(bool)"false"` is `true` in PHP — a generic cast is not a Boolean contract. |
| number / int / integer | numeric string (e.g. `"42"`) — **grammar to be specified** | `is_numeric()` is not a business contract. Rules: validated numeric lexical representation kept as a string; no automatic conversion on reads; no silent rounding/clamping; **no canonical rewriting of legacy** `"01"`/`"1.0"` without consumer evidence. Grammar + exponent handling remain OPEN until consumers are characterized. |
| select **with** options | string ∈ options | exact declared value; **stale option rule:** removing an option must not invisibly replace an existing override — reads preserve the raw value and report validity; writes reject an invalid new choice without blocking unrelated changes |
| select **without** options (14 cases) | **legacy exception — classify, do not reject** | classify: fixed enum with omitted options / dynamic option source / legacy free-form string / abandoned declaration. No categorical rejection of historical values. |
| text / textarea / email / time | string | semantic validation (email syntax? time format/timezone?) must be specified separately — a `time` field is NOT necessarily parser-governed today |
| password / secret | string at rest; blank input on **write** means unchanged | the sentinel belongs to the write operation, not the stored value. Separate `unchanged` / `replace` / `clear` actions. |
| arrays / objects | **out of scope for scalar v1** | classify the 2 existing array rows (exact keys, writers, readers, purpose) and grandfather them without interpreting or rewriting. |

**`_`-prefixed keys:** a blanket exemption is **REJECTED** — a prefix is a naming convention, not proof of ownership. Two explicit categories instead: **declared configurable settings** (public contract) and **internal module metadata** (explicitly classified, owned, excluded from public validation). Unknown stored keys are inventoried and classified before anyone rejects them.

**Distinctness rules (normative):**
- **absent** (no row) ≠ `""` ≠ `false` ≠ `0` ≠ `"0"` — all five are different states.
- Consumers MUST NOT use PHP truthiness to distinguish them; use `array_key_exists` / strict comparisons. New code violating this fails review.

## 2. Blank semantics (the 51-row hazard — 24.4% of stored rows)

- **Ruling (chair):** adopt an optional per-field declaration `blank_means: inherit | value | reject` — but **do not change runtime behavior from it in this cycle**; the annotation describes existing behavior, it does not authorize changing it.

| policy | blank write | effective resolution |
|---|---|---|
| `inherit` | stored as today | blank is skipped and the fallback applies (today's merge-helper behavior) |
| `value` | stored as today | blank **is** the effective value |
| `reject` | rejected at write | fallback preserved |

- Do not apply `inherit` as a new default to every field. A field whose effective behavior is `inherit` must not be described as supporting an explicit empty override.
- Distinguish a blank **submitted** form field from a **missing** field in the request — they must not imply the same write.
- Gate 2 work: document the currently observed resolution behavior of each affected consumer; explicitly list fields where blank is meaningful; require tests before any field adopts the attribute.
- The proven skip-empty rule in existing merge helpers (AI blank-masking bug) is the concrete instance of `inherit` — keep it; the A1 characterization suite guards it.

## 3. Default-change policy

- Changing a manifest `default` is a **compatibility event** — every tenant without an override silently changes behavior (Gate 0 verified this is the current mechanics).
- Rules:
  1. Defaults must preserve observable behavior. A behavior-changing default requires explicit owner sign-off in the commit message and release notes.
  2. Sign-off evidence list (chair): old and new **effective** values; the consumer whose behavior changes; tenants lacking an override; **tenants holding a stored `""`** (skip-empty consumers receive the changed fallback too — they cannot be excluded); the rollback path.
  3. **Snapshot ruling (chair): ADOPT — as a reviewable normalized artifact**, not hash-only: deterministic committed content covering keys, declared types, presence/absence of defaults, normalized default values, select options (per-module hashes optional). CI then shows a meaningful diff.
     **Coverage warning (label it):** the snapshot captures the **declared default** only — the **effective fallback** produced by `*SettingsDefaults()` helpers is a different layer and needs behavioral tests for high-impact consumers.
  4. Do NOT build a fleet-wide default-diff engine yet: fleet inventory + helper coverage come first (one fixture tenant ≠ fleet evidence).

## 4. Rename / deprecation policy

- New optional attributes (additive): `deprecated_since`, `superseded_by`, `migration: "alias"`. An alias is a **declared, testable key rename — never a type conversion or value transformation**.
- **Conflict ruling (chair) — report reads, stop writes:**

| Operation | Both keys present | Ruling |
|---|---|---|
| Compatibility read | ambiguous | **Report the conflict; preserve previously established behavior** — never fail a production read into an outage; if prior precedence is unknown, MEASURE it, do not invent one |
| Administrative mutation | ambiguous | **Reject** until resolved |
| Automated migration | ambiguous | **Stop that record**; require resolution |
| Removal of old key | old rows remain | **Reject removal** |

- Removal gates: fleet-wide zero rows is **necessary but not sufficient** — also verify static reads/writes, background consumers, API clients, and **mixed deployments** (a minimum writer version must be required, or prove old-key writes have stopped, before cleanup).
- No runtime dual-key resolver — that would become the central resolver this cycle forbids; rename stays a migration protocol.
- Field-specific fail-closed exceptions only for security-sensitive settings (tenant isolation / authorization / credential security), backed by an impact assessment — not a universal rule.

## 5. Diagnostic record — ECI `contract:explain setting`

One record per (tenant, module, key):
- declared type · manifest default · stored raw value (**or absent**) · effective value
- **effective value computed via the SAME path the consumer uses**: kernel resolver + the module's merge helper where one exists; where none exists, label the record `kernel-only resolution` (honest scope, not a claim).
- source precedence: `manifest-default` | `tenant-override` | `fallback`
- validity (type match vs declared) · deprecation status · **manifest revision** (hash of the field entry, so "why now?" can be tied to a deploy)

Non-goals: no writes, no activations, no cross-tenant enumeration; caller-scoped.

**Amendments (chair):**
- **Four layers, kept separate:** raw state (present/absent, raw type, raw value) · manifest declaration (type/default/options/revision) · resolved state (**consumer identity** + effective value + precedence provenance) · diagnostic state (valid/invalid/unknown; deprecated/conflicted; evidence coverage).
- **`unverified` is not `effective`:** where the real consumer path is unavailable to the inspector, report `unknown/unverified` — never present a kernel-only approximation as the effective value (an approximation drift path would become a second settings resolver).
- **Secrets:** expose presence, type and safe fingerprints — redact raw secret/password values; access-control the diagnostic.

## 6. Enforcement staging (what may land when)

0. **Now (tests only):** characterization suite — **LANDED 2026-10-12** (A1: 34 → 50 checks; fleet invariants, checker must-refuse fixtures, round-trip distinctness, cleanup verified).
1. **First enforcement (chair's smallest step): advisory manifest contract linter + committed normalized baseline.** Validates the closed 9-type vocabulary; rejects NEW duplicate / missing-type declarations; reports missing defaults and select-without-options **allowing documented exceptions**; produces the deterministic snapshot diff (§3). Runs in CI: **warnings for legacy, fail only on NEW unambiguously-invalid regressions.** Non-invasive: touches no runtime read or write.
2. **After Gate 2 differential tests per path:** write-side canonicalization only in characterized branches with proven identical behavior (the `bool` write path is the first candidate once measured) + ECI diagnostic records.
3. **Not this cycle:** read-side normalization of legacy values, platform-wide migrations, any central resolver, a fleet-wide default-diff engine.

**Write-path scope (chair):** canonical guarantees apply only to **audited writer paths**. HTTP handlers are the measured coercion boundary; CLI scripts, migrations, provisioning, module jobs and direct SQL are hypotheses needing inventory — do not label storage **canonical** until every production writer is identified or brought under the same rules.
