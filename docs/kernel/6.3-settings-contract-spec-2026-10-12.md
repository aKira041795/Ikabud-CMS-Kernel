# Settings Contract Spec — Kernel OS 6.3, Track A (Gate 2 "specify" half)

**Status: DRAFT v0.1 — PROPOSED. Awaiting chair review and owner approval.**
No enforcement may land from this spec until Gate 2 differential tests prove compatibility on each consuming path.
**Date:** 2026-10-12 (night session)

**Basis:**
- Chair rulings (settings consult + consolidation consult): characterize → specify → enforce only proven; a central normalizer must never become a second settings authority; per-module `*SettingsDefaults()` helpers are the coverage boundary; `false`/`0`/`""`/`null`/absent must be distinct; rename conflicts stop and report; default changes are compatibility events.
- Gate 0 measurements (2026-10-12/13):
  - **Fields:** 70 modules, 27 with `settings_fields`, **390 fields**. Types: text 168, checkbox 77, select 61, number 55, textarea 16, email 5, password 4, bool 3, time 1.
  - **Invariants:** 0 duplicate keys, 0 missing types, 21 fields without `default`, **14 select fields without `options`**.
  - **Stored (local tenant):** 209 rows, 29 modules. Types: string 155, boolean 50, array 2, integer 2. **51 empty strings**, 8 string-`"1"`, 2 string-`"0"`.
  - **Write coercion** lives in the HTTP handlers only (admin `admin-handlers.php:2810-2845`, superadmin equivalent): checkbox→bool, number→numeric string, select→options-checked string, else `trim(string)`.
  - **Read path:** JSON round-trip preserves `false` / `""` / `0`; absent keys stay absent; the kernel does **not** merge manifest defaults — per-module helpers do.

## 1. Value model (canonical stored form per declared type)

| Declared type | Canonical stored form | Notes |
|---|---|---|
| checkbox / bool / boolean | JSON `true` / `false` | `"0"`/`"1"`/`"true"` strings found in the store are legacy; characterize each consumer before any normalization |
| number / int / integer | numeric string (e.g. `"42"`) | matches current handler coercion; switching to JSON numbers is NOT in this cycle |
| select **with** options | string ∈ options | enforced by the handler on write today |
| select **without** options (14 cases) | free-text string | **anomaly list to remediate**: add options or re-type to `text` (separate decision, not this cycle) |
| text / textarea / email / time | string | |
| password / secret | string; empty string on write = "unchanged" sentinel | superadmin handler skips empty secrets |

**Distinctness rules (normative):**
- **absent** (no row) ≠ `""` ≠ `false` ≠ `0` ≠ `"0"` — all five are different states.
- Consumers MUST NOT use PHP truthiness to distinguish them; use `array_key_exists` / strict comparisons. New code violating this fails review.

## 2. Empty-string policy (the 51-row hazard)

- A stored `""` is **"explicitly empty"**, not "unset".
- However, the established merge convention for manifest defaults (proven necessary in the AI module) is: **manifest-default merge helpers skip empty-string stored values** — a blank stored value must not mask a manifest default.
- Spec rule going forward: every manifest-default merge helper must implement the skip-empty rule; the A1 characterization suite tests it.
- Fields where `""` is a *meaningful value* (not "unset") must be explicitly listed here with a test. *(Open: none identified yet — enumerate during Gate 2 characterization.)*
- **Open question for chair:** is an explicit per-field attribute (`blank_means: unset|value`) warranted, or is documented + tested convention sufficient?

## 3. Default-change policy

- Changing a manifest `default` is a **compatibility event** — every tenant without an override silently changes behavior (Gate 0 verified this is the current mechanics).
- Rules:
  1. Defaults must preserve observable behavior. A behavior-changing default requires explicit owner sign-off in the commit message and release notes.
  2. The effective-value diagnostic must be able to list **which tenants (without overrides) change** for a given default edit — that listing is required evidence for the sign-off.
  3. Proposed regression gate: a per-module **defaults snapshot** (hash of `settings_fields[].default` values) committed under `tests/` — changing a default requires updating the snapshot in the same commit, making silent drift impossible and intentional changes visible in the diff. *(Open question for chair: churn vs value.)*

## 4. Rename / deprecation policy

- New optional field attributes (additive, no manifest breakage): `deprecated_since` (date), `superseded_by` (new key), `migration: "alias"`.
- **Read during deprecation:** both keys are read. If **both** have stored values → **STOP**: report the conflict (diagnostic record + log); never silently pick a winner.
- **Write during deprecation:** the new key is preferred; writing the deprecated key emits a deprecation warning in the response payload.
- **Migration:** explicit script (per-tenant or fleet), idempotent, preserves explicit overrides by materializing old→new; refused with a report list when both keys hold *different* values.
- **Removal:** only after N releases **and** a fleet-wide diagnostic confirms zero rows for the old key.

## 5. Diagnostic record — ECI `contract:explain setting`

One record per (tenant, module, key):
- declared type · manifest default · stored raw value (**or absent**) · effective value
- **effective value computed via the SAME path the consumer uses**: kernel resolver + the module's merge helper where one exists; where none exists, label the record `kernel-only resolution` (honest scope, not a claim).
- source precedence: `manifest-default` | `tenant-override` | `fallback`
- validity (type match vs declared) · deprecation status · **manifest revision** (hash of the field entry, so "why now?" can be tied to a deploy)

Non-goals: no writes, no activations, no cross-tenant enumeration; caller-scoped.

## 6. Enforcement staging (what may land when)

1. **Now (tests only):** characterization suite (A1 lane: fleet invariants, checker must-refuse fixtures, round-trip distinctness, skip-empty rule).
2. **After Gate 2 differential tests per path:** write-side canonicalization *only where handlers already coerce identically today* (zero behavior delta) + ECI diagnostic records.
3. **Not this cycle:** read-side normalization of legacy values, platform-wide migrations, any central settings resolver.
